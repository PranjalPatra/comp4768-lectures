The Problem with Null

Learning outcomes

By the end of this lecture, you should be able to:

  • distinguish non-nullable and nullable types;
  • use null checks, ?., ??, ??=, and !;
  • declare nullable parameters and return types; and
  • choose between a nullable variable and late.

null means that a value is absent. Using an absent value as if it were an object can crash a program.

bool isEmpty(String text) => text.length == 0;

void main() {
  isEmpty(null); // Compile-time error
}

Current Dart rejects this call before the program runs.

Sound Null Safety

Dart has sound null safety:

  • a non-nullable variable cannot contain null;
  • a nullable variable is marked with ?; and
  • Dart requires nullable values to be handled before unsafe use.

The type tells us whether absence is possible.

Non-Nullable by Default

Types are non-nullable by default. A variable of type String must always hold a string.

void main() {
  String course = 'COMP 4768';
  print(course.length);

  // course = null; // Compile-time error
}

Add ? to a type when absence is a valid state.

int? score;

  print(nickname);

  nickname = null;
  print(nickname);

Question

Which declarations are accepted: top-level int a;, int? b;, int c = null;, and String? d = 'x';?

Answer

int? b; and String? d = 'x'; are accepted. Top-level int a; has no value for its non-nullable type, and int c = null; tries to store null in a non-nullable variable.

Checking for Null

A null check separates the absent case from the case that has a value.

String greeting(String? name) {
  if (name != null) {
    return 'Hello, $name!';
  }
  return 'Hello, mysterious user!';
}

void main() {
  print(greeting('Ada'));
  print(greeting(null));
}
Hello, Ada!
Hello, mysterious user!

The ?? Operator

The ?? operator uses the value on its left unless that value is null. Otherwise, it uses the value on its right.

String displayName(String? nickname) {
  return nickname ?? 'Guest';
}

void main() {
  print(displayName('Dash'));
  print(displayName(null));
}
Dash
Guest

The ??= Operator

The ??= operator assigns only when the variable is currently null.

void main() {
  int? score;

  score ??= 5;
  score ??= 10;

  print(score);
}
5
Question

Suppose String? foo = 'a string'; and String? bar;. Fill the operators: String? baz = foo ___ bar; and bar ___ 'a string';. Then evaluate null ?? 12 and 1 ?? 3.

Answer

Use ?? in the first blank and ??= in the second. The expressions produce 12 and 1.

Conditional Access

The ?. operator accesses a member only when the value before it is not null.

void main() {
  String? message = 'Hello World';
  print(message?.toLowerCase().length);

  message = null;
  print(message?.toLowerCase().length);
}

Question

If message is null, does message?.toLowerCase().length call either member? What value does the whole expression produce?

Answer

It calls neither member. Conditional access stops at null, and the whole expression produces null.

The ! Operator

The ! operator asserts that a nullable value is not null. The program fails at runtime if the assertion is wrong.

int characterCount(String? text) {
  return text!.length;
}

void main() {
  print(characterCount('Dart'));
  print(characterCount(null));
  print('Done');
}
Question

What does the first call print? Does the program reach print('Done')?

Answer

The first call prints 4. The second call applies ! to null and throws at runtime, so the program does not print Done.

Nullable Parameters

A parameter can accept null when its type is nullable.

void greet({String? middleName}) {
  print(middleName ?? 'No middle name');
}

void main() {
  greet(middleName: 'Grace');
  greet();
}
Grace
No middle name

Nullable Return Values

A function uses a nullable return type when a valid call may produce no value.

String? upperCaseIt(String? str) => str?.toUpperCase();

void main() {
  print(upperCaseIt('Dart'));
  print(upperCaseIt(null));
}
DART
null

Map Lookup Revisited

A map lookup returns a nullable value because the requested key may not exist.

void main() {
  var distances = {
    'Earth': 0.0,
    'Venus': 41.0,
  };

  print(distances['Mars']);
  print(distances['Mars'] ?? 0.0);
}
null
0.0

Question

For String joinWithCommas(int a, [int? b, int? c]), trace the call joinWithCommas(1, 2). Which parameter is null, and what must the function body check?

Answer

a is 1, b is 2, and c is null. The body must check whether each nullable optional parameter is present before adding it to the result.

AI Explanation

The Problem with Null

L2 showed that a missing map key produces null. L3 used String? email and required this.red. This lecture explains the rules behind that syntax.

The parameter type String promises a real string. Passing null breaks that promise, so Dart reports a compile-time error before the program starts.

This early check is useful in Flutter applications. The developer sees the problem during development instead of waiting for a user to reach the faulty line.

Sound Null Safety

Sound means that Dart enforces the type promise throughout the program. If a value has type String, code can use String members without checking for null first.

If a value has type String?, Dart requires the code to check, provide a fallback, use conditional access, or make an assertion before using String members.

Null safety moves many mistakes from runtime to compile time. It does not remove null; it makes possible absence visible in the type.

Non-Nullable by Default

The declaration gives course a valid string immediately. Every later assignment must also supply a String.

The commented assignment is rejected because null is not a String. The compiler therefore knows that course.length is safe.

Types such as int, double, bool, String, collection types, and user-defined class types are non-nullable unless their type name ends with ?.

Nullable Types

Top-level and static variables that have nullable types start as null when no initializer is written. The example places score at the top level so it can be read safely in main.

An uninitialized nullable variable starts as null. This also applies to a local declaration such as String? name;.

The diagram shows the two possible states. A String? variable can hold a String value or null. A String variable has only the first possibility.

Checking for Null

Before the if statement, name has type String?. Inside the branch where name != null, Dart knows that name contains a string.

This temporary narrowing is called type promotion. The check proves that the value is non-null along that path through the function.

The second return handles the absent case. Write both cases explicitly when the program needs different behavior for each one.

The ?? Operator

The first call returns 'Dash' because the nullable value is present. The second returns 'Guest' because the left side is null.

The right side is evaluated only when it is needed. This makes ?? useful for a fallback value that may take work to produce.

Use ?? when the program needs one expression representing a value or a fallback when it is absent.

The ??= Operator

The first assignment runs because score starts as null. It stores 5. The second assignment does nothing because score already has a value.

The operator does not test whether a number is zero or whether a string is empty. It tests only for null.

Compare the two operators: value ?? fallback produces a value, while variable ??= fallback may change a variable.

Conditional Access

With a non-null string, ?. accesses the same member that . would access. With null, the access is skipped and the whole chain evaluates to null.

In current Dart, one ?. at the start makes later accesses in the same chain conditional too. You can also chain through values that are themselves nullable:

user?.address?.city

The result of conditional access is nullable because one possible result is absent. For example, message?.length has type int?.

The ! Operator

The type String? says that absence is possible. The ! operator is the programmer's claim that the value is present at this exact point.

The assertion changes what the type checker allows. It does not check or repair the data. For example, json['name']! throws if the map contains no 'name' key.

Prefer a null check, ?., or ?? when those operators express the intended behavior. Use ! only when another fact guarantees that the value cannot be null and Dart cannot prove that fact.

Nullable Parameters

The caller may omit middleName because its type allows null. An omitted optional named parameter receives null when no default is provided.

A non-nullable named parameter needs a default value or the required modifier. This explains the constructor form from L3:

MyColor({required this.red, required this.green, required this.blue});

Without required or defaults, callers could omit the arguments and leave the non-nullable fields without values.

Nullable Return Values

The return type String? tells every caller to handle two possibilities. A non-null input produces an uppercase string, while a null input produces null.

The ?. operator makes the function concise because the desired output is also absent when the input is absent.

A non-nullable return type such as String would promise that every path returns a string. That promise would require a fallback or some other handling for the null case.

Map Lookup Revisited

L2 showed that a missing map key produces null. Null safety explains the type behind that behavior: a lookup in Map<String, double> returns double?.

The first lookup finds no 'Mars' key and returns null, as it did in L2. The second lookup asks for the same missing key, then ?? supplies 0.0.

A fallback is correct only when it has the intended meaning. In a distance calculation, zero might incorrectly mean the same location. Another program may need to display unknown or handle the missing key separately.

Late and Nullable Variables

Use late when initialization must happen later but the completed program still requires a value. Reading a top-level late variable before assigning it throws a LateInitializationError:

late String token;

void main() {
  print(token); // Runtime error
}

Use a nullable type when no value is a valid state that the program should handle. Changing a nullable variable to late replaces explicit handling with a promise that can fail at runtime.
