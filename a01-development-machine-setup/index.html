Phase 1 Tools

Learning outcomes

When setup is complete, you should be able to create, analyze, test, run, and build a Flutter application on the course emulator.

Phase 1 prepares your computer for the course. Install:

  • Git and GitHub CLI;
  • Flutter and Dart;
  • Android Studio and the Android SDK;
  • a Pixel 9a Android emulator;
  • Firebase CLI; and
  • FlutterFire CLI.

Do not install Codex or agent skills yet. Those tools belong to Phase 2.

Requirements and Accounts

SystemSupported computer
Windows64-bit Intel or AMD, Windows 10 or 11
macOSApple silicon or Intel Mac
Linux64-bit Intel or AMD, Ubuntu or Debian

For every system:

  • 8 GB memory minimum, with 16 GB recommended;
  • at least 35 GB free storage;
  • a Google account; and
  • a GitHub account.

Windows on ARM and Linux on ARM are not supported by Android Studio for this setup.

Create one Android Virtual Device with this configuration:

Use ARM64 on an Apple silicon Mac. Use x86_64 on Windows, Linux, and an Intel Mac.

Windows Flutter and Virtualization

Download the current stable Flutter SDK from Flutter installation. Extract it to:

C:\src\flutter

Add these folders to your user Path:

C:\src\flutter\bin
%LOCALAPPDATA%\Pub\Cache\bin

Do not put Flutter in Program Files or OneDrive.

Windows Android Tools

Install the current stable Android Studio and finish its setup wizard.

Open File -> Settings -> Languages & Frameworks -> Android SDK. Install:

  • Android 17, API 37;
  • Android 16, API 36;
  • Android SDK Build-Tools and Platform-Tools;
  • Android SDK Command-line Tools (latest);
  • Android Emulator;
  • CMake; and
  • NDK (Side by side).

AI Explanation

Phase 1 Tools

Follow only the section for your operating system. Use PowerShell on Windows and a normal terminal on macOS or Linux.

Several downloads are large. Start early enough to resolve installation, account, or virtualization problems before the submission deadline.

The three operating-system sections lead to the same result. Their commands differ because installation paths, package managers, and virtualization support differ.

Requirements and Accounts

Linux setup also requires permission to use sudo. Windows students should use PowerShell for every command in this guide.

The Android emulator uses a large part of the recommended memory. A computer with 8 GB can meet the stated minimum, but 16 GB should provide a smoother experience while Android Studio and the emulator run together.

Use course accounts that you can access throughout the term. The final verification checks both GitHub and Firebase sign-in.

Course Emulator

Do not choose a Beta, Preview, Canary, or QPR Beta system image. Keep graphics acceleration on Hardware or Automatic.

If Pixel 9a is missing from Device Manager, update Android Studio and Android Emulator. If it is still missing, create a hardware profile named Pixel 9a Course with a 6.3-inch screen, 1080 x 2424 resolution, 4096 MB RAM, and 420 dpi density.

The virtual-device name matters because the verification log checks it. Wait for the Android home screen before running the Flutter application.

Windows Basic Tools

Configure Git with your own name and email, then sign in to GitHub:

git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
gh auth login --web
gh auth status

Finish the GitHub sign-in page in your browser. The final gh auth status command should identify the account that you intend to use for the course.

Windows Flutter and Virtualization

Reopen PowerShell and check Flutter:

where.exe flutter
flutter channel stable
flutter upgrade
flutter --version
dart --version

Open Task Manager -> Performance -> CPU and confirm that it reports Virtualization: Enabled. If it is disabled, enable Intel VT-x, AMD-V, or SVM in BIOS or UEFI.

Enable Windows Hypervisor Platform in Windows Features, then restart Windows.

Windows Android Tools

Click Apply and wait for every download to finish. Then accept the Android licenses:

flutter doctor --android-licenses
flutter doctor -v

Read each license and type y when you agree. The Android toolchain and Android Studio sections should not show an error. Warnings for other platforms can be ignored.

In Tools -> Device Manager, create the course emulator using the common configuration at the beginning of this guide. Windows uses the x86_64 Google Play image.

Windows Firebase and Test App

Use the Google account for this course. A Firebase-enabled Flutter project will later use:

flutterfire configure --platforms=android
firebase init emulators
firebase emulators:start

Start Pixel_9a_API_37, list the available devices, and run the test app:

flutter devices
flutter run -d <emulator-device-id>

Replace <emulator-device-id> with the ID printed by flutter devices. It often looks like emulator-5554. Press q to stop the app, then run flutter build apk --debug.

Windows Verification

The log should show Android 17, API 37, and the AVD name Pixel_9a_API_37. Flutter Doctor should report no Android toolchain error.

It should also show successful Flutter analysis, tests, and debug APK build, along with signed-in GitHub and Firebase accounts.

Do not submit passwords, access tokens, recovery codes, private keys, or Firebase service-account files.

Linux Basic Tools and KVM

Reopen Terminal, check the tools, configure Git with your own name and email, and sign in:

git --version
gh --version
node --version
npm --version
java --version
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
gh auth login --web
gh auth status

Check virtualization:

egrep -c '(vmx|svm)' /proc/cpuinfo
kvm-ok
sudo usermod -aG kvm "$USER"

The first command should print a number greater than zero, and kvm-ok should report that acceleration can be used. Enable VT-x, AMD-V, or SVM in BIOS or UEFI if needed. Log out and back in after changing the KVM group. Do not run Android Studio or the emulator as root.

Linux Flutter and Android Tools

Download Android Studio, follow Google's Linux installation instructions, and finish its setup wizard.

Under Settings -> Languages & Frameworks -> Android SDK, install Android 17 API 37, Android 16 API 36, Build-Tools, Command-line Tools, Emulator, Platform-Tools, CMake, and NDK.

Click Apply, then run:

flutter doctor --android-licenses
flutter doctor -v

Read each license and type y when you agree. The Android toolchain and Android Studio sections should not show an error. Warnings for other platforms can be ignored.

Linux Emulator

If the Pixel 9a device is missing, use the fallback hardware profile described at the beginning of this guide.

Do not select a Beta, Preview, Canary, or QPR Beta image. Keep graphics acceleration on Hardware or Automatic.

If the emulator does not start, recheck kvm-ok and your KVM group membership before changing the emulator configuration.

Verification and Submission

The three log filenames are:

  • Windows: phase1_windows_setup.txt
  • macOS: phase1_macos_setup.txt
  • Linux: phase1_linux_setup.txt

Open the file and read it before submitting. Command logs can contain more information than expected. Remove secrets rather than submitting passwords, tokens, recovery codes, private keys, or service-account files.

If a check fails, return to the matching setup slide and correct the installation before creating the final log.
